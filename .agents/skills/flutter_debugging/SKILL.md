# Flutter Debugging Best Practices

When debugging the Flutter app, rely on the following workflows to diagnose issues quickly.

## 1. Essential Flutter CLI Commands
*   `flutter run`: Launches your app. While running, use interactive keys:
    *   `r`: Hot reload.
    *   `R`: Hot restart.
    *   `d`: Detach (leaves the app running but disconnects the CLI).
    *   `q`: Quit/terminate the application.
*   `flutter attach`: Connects the Flutter CLI to an already running app. This unlocks hot reload and DevTools access without restarting.
*   `flutter analyze`: Performs static analysis to find code errors or missing implementations.
*   `flutter clean`: Removes build artifacts. Useful when encountering obscure build errors.

## 2. Android Logcat
Logcat is the primary logging system for Android. Since Flutter logs are integrated into the system output, you can view them via ADB.
*   **View Flutter logs**: `adb logcat -s flutter` (captures logs generated by Dart code).
*   **Clear log buffer**: `adb logcat -c`
*   **Best Practice**: In Dart code, use `debugPrint()` instead of `print()`. `debugPrint()` is throttled to prevent Android from discarding log lines if outputting too much data at once.

## 3. Dart/Flutter DevTools
DevTools is a web-based suite of performance and debugging tools.
*   **Inspector**: Visualizes the widget tree and helps debug layout/UI issues.
*   **Debugger**: Set breakpoints, step through code, and inspect variables.
*   **Network**: Monitors HTTP requests and responses.
*   **Memory**: Tracks heap usage to find memory leaks.
*   **How to launch**: DevTools URL is printed in the console when running `flutter run` or `flutter attach`.

## Troubleshooting Tips
*   If Flutter hot reload fails, try `flutter clean` and then run again.
*   When fixing complex state issues in Riverpod or Provider, prefer hot restart (`R`) over hot reload (`r`).
